# Zu Sprachgarten beitragen

- Fehler mit Windows-Version, App-Version, erwartetem Verhalten und einem kleinen künstlichen Beispiel beschreiben.
- Keine persönlichen Diktate, Aufnahmen, Benutzerpfade, Kontodaten oder Tokens anhängen. Auch Screenshots und Testprotokolle prüfen.
- Für Änderungen einen eigenen Branch und einen Pull Request verwenden. Beschreiben, was sich ändert und welche Tests tatsächlich liefen.
- Bestehende Nutzerdaten erhalten. Mikrofon- und hörbare Wiedergabetests ausdrücklich ankündigen.
- Compilererfolg, Komponententests, native Bedienung und menschliche Klangbewertung getrennt angeben.
- Vor einem Commit `git diff --cached` kontrollieren. Nur beabsichtigte Dateien hinzufügen; ignorierte Dateien nicht mit `git add -f` erzwingen.
- Eine GitHub-Noreply-Adresse kann verhindern, dass die private E-Mail in Commits erscheint. Den öffentlichen Autorennamen bewusst wählen.

Beiträge sollen unter derselben MIT-Lizenz wie der Projektcode nutzbar sein. Fremden Code und Medien nur mit belegten Nutzungsrechten und erforderlichen Lizenzhinweisen ergänzen.
